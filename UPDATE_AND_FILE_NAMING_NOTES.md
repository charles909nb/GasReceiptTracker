# Signing, upgrades, and fuel-document names (October 2026)

The previous GitHub Actions job emitted `app-debug.apk`. GitHub-hosted runners are disposable, so their autogenerated debug signing key may change with every run. Android requires the **same application ID, signing certificate, and a higher versionCode** when installing an update over an existing app.

## Stable APK signing: one-time setup

1. Create a secure, long-lived **private** Android keystore **once**, and keep an offline backup of the keystore and passwords. **Do not upload the raw keystore, passwords, or private signing keys into this public repository.**
2. In this repository's **Settings > Secrets and variables > Actions**, configure:
   - `GRT_SIGNING_KEYSTORE_B64`: base64 of the entire private JKS keystore.
   - `GRT_SIGNING_STORE_PASSWORD`: keystore password.
   - `GRT_SIGNING_KEY_ALIAS`: key alias.
   - `GRT_SIGNING_KEY_PASSWORD`: key password.
3. On the next `main` workflow run, download the artifact **GasReceiptTracker-Signed-Update-APK**. It uses the stable package ID `org.karuk.gasreceipttracker` and an increasing Android `versionCode`.
4. Future updates installed from the same **signed release** stream should install over existing signed-release builds and keep app data. **Verify app updates on a test phone before relying on them.**

Until those four secrets are configured, the workflow produces only a clearly labelled **PREVIEW-NOT-FOR-UPDATES** artifact. A preview build uses the package suffix `.preview`; it is not a substitute for the signed release.

## One-time migration warning

**A new signing key cannot update an Android app installed under a different signing certificate.** Earlier debug-preview installs may require one final replacement. **First use the app's Backup function, save the ZIP outside the app, and verify it exists.** Then install the newly signed release and restore the ZIP. Do not uninstall an app that has no verified backup. If your existing app's original signing keystore is available, reuse it instead of creating a new signing identity.

The new naming convention for fuel receipts/packets is:
`YYYY-MM-DD_Purchase_Request_Fuel_<VehicleNumber>.pdf`
and for official Excel export:
`YYYY-MM-DD_Purchase_Request_Fuel_<VehicleNumber>.xls`

Examples: `2026-10-14_Purchase_Request_Fuel_309.pdf`. If an export with that name already exists but is **a different** packet, an eight-character content suffix is added to avoid overwriting it. The official worksheet bytes, layout, and metadata have **not** been changed.
